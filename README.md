# Little Shield

אפליקציית בטיחות שנועדה להפחית את הסיכון שהורה ישכח ילד ברכב.

הרעיון במשפט אחד: **האפליקציה מזהה לבד שנסיעה הסתיימה ושההורה מתרחק מהרכב,
ושואלת אותו אם כל הילדים יצאו.** אם אין תגובה — אזהרה שנייה, ואחריה מסך
שמציע להתקשר לאיש קשר שההורה הגדיר מראש.

האפליקציה **לעולם לא טוענת שהיא יודעת שילד נשאר ברכב**, כי היא לא יודעת.
הניסוח בכל מסך ובכל התראה הוא שאלה ("בדקת שכל הילדים יצאו?") ולא האשמה.

---

## הרצה על המחשב

פעם אחת, אחרי הורדת הפרויקט:

```bash
npm install
```

## בנייה לקובץ התקנה (APK)

זו הדרך לבדוק את האפליקציה. **Expo Go לא רלוונטי כאן** — הוא לא כולל את
המודול הנייטיב ולכן ההגנה האוטומטית, שהיא כל הרעיון, לא עובדת בו.

```bash
set EAS_NO_VCS=1 && npx eas-cli build --profile preview --platform android
```

`EAS_NO_VCS=1` נדרש **רק כל עוד אין git מותקן על המחשב**. אחרי התקנת
Git for Windows אפשר להוריד אותו, ובנוסף תהיה היסטוריית שינויים — מומלץ
מאוד בפרויקט שכבר איבד קבצים בעבר.

## בדיקות

```bash
npm test
```

64 בדיקות אוטומטיות שמכסות את תרחישי הבטיחות: נסיעה מלאה, חוסר תגובה,
הליכה ברגל שאסור שתייצר אזהרה, חידוש נסיעה, ושרידות אזהרה לסגירת האפליקציה.

```bash
npx tsc --noEmit
```

בדיקת טיפוסים. צריכה לעבור נקייה.

## מבנה הפרויקט

```
src/config.ts              כל הספים והזמנים. אסור למספרים כאלה לשבת בקוד אחר.
src/services/
  tripStateMachine.ts      מכונת מצבים טהורה. בלי GPS, בלי זמן מערכת, בלי side effects.
  tripDetection.ts         זיהוי תחילת/סוף נסיעה מרצף דגימות. פונקציות טהורות.
  geoUtils.ts              מרחקים ובדיקת יציאה מ-geofence.
  tripStateService.ts      המתזמר: מזין קלטים למכונה ומבצע את האפקטים שהיא מבקשת.
  locationService.ts       עטיפת expo-location + מאגר דגימות.
  geofenceService.ts       ניהול ה-geofence סביב נקודת העצירה.
  backgroundTasks.ts       רישום משימות רקע.
  protectionService.ts     מדליק/מכבה הגנה, מחבר התראות וניווט.
  eventLog.ts              יומן אירועים בזיכרון. מזין את מסך ה-Debug.
  mockLocation.ts          מחולל דגימות מדומות לבדיקות ולסימולציה.
src/storage/               שמירה מקומית מעל AsyncStorage.
src/notifications/         תזמון התראות ותזכורות.
modules/vehicle-detection/ מודול נייטיב (Kotlin) לאנדרואיד: Activity Recognition.
app/                       מסכים (Expo Router).
```

העיקרון המרכזי: **מכונת המצבים לא יודעת דבר על מערכת ההפעלה.** היא מקבלת
קלט ומחזירה מצב חדש ורשימת פעולות לביצוע. המתזמר הוא זה שמבצע אותן. זו
הסיבה שאפשר לבדוק את כל תרחישי הבטיחות אוטומטית, בלי לצאת לכביש.

## שני מנגנוני זיהוי, לפי פלטפורמה

**אנדרואיד** — Activity Recognition (יציאה מרכב) הוא הסיגנל הראשי. המקלט
מוצהר במניפסט ולכן מתעורר גם כשהאפליקציה סגורה לגמרי, וההתראה נשלחת מקוד
Kotlin כי ה-JavaScript לא רץ באותו רגע.

**iOS** — אין API חשוף ב-Expo לזיהוי יציאה מרכב. שם הסיגנל היחיד הוא
geofence סביב נקודת העצירה. **הזיהוי באייפון חלש מהותית מאנדרואיד** —
זו מגבלת מערכת, לא חוסר בקוד.

## מלכודת ידועה בבנייה

גרסאות של `play-services-location` מ-21.4.0 ומעלה קומפלו עם Kotlin 2.3,
בעוד Expo SDK 57 מקמפל עם Kotlin 2.1. שדרוג הגרסה הזו יפיל את הבנייה עם
"Module was compiled with an incompatible version of Kotlin". הגרסה
נעוצה בכוונה ב-21.0.1 ב-`modules/vehicle-detection/android/build.gradle`.

## הערה על RTL

`I18nManager.forceRTL` דורש טעינה מחדש של האפליקציה כדי להיכנס לתוקף באופן
מלא. בהרצה הראשונה ייתכן שתראה איפוס אוטומטי — זו התנהגות תקינה של
React Native, לא באג.
